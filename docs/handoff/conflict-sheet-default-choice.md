# 핸드오프: 충돌 시트 — 더 최신 것만을 기본 선택, "지금 결정 기억하기"

R1에서 인간과 합의한 내용의 기록. R2(테스트 코드 작성)·구현의 유일한 입력이다.
이 문서에 없는 케이스는 완료 범위 밖이다. 새 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

작업 유형(R0): **기능(UI 동작 변경) 1건**. 충돌 시트(`ConflictSheet`)의 결정 방식만 바꾼다.
충돌을 찾는 쪽(main `transfer:send`의 `conflicts`·`decisions`)과 결정의 뜻은 바꾸지 않는다.

> 사용자 피드백: "파일명 충돌 시 최신 파일로 덮어쓰기를 기본 선택 사항으로 두고 지금 결정 기억하기 라디오를 하단에 두자."

---

## 1. 지금 동작

시트는 단추 네 개(둘 다 두기·덮어쓰기·더 최신 것만·건너뛰기)를 보인다. 누르면 그 결정이 곧바로 적용된다.
기본으로 눈에 띄는 것은 "둘 다 두기"(주 단추, 처음 포커스)이고, 결정을 기억하는 길은 없다.
같은 폴더를 반복해 올릴 때마다 같은 결정을 다시 눌러야 한다.

## 2. 결정 (R1)

| #   | 결정                                                                                                                                                                                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | 단추 네 개를 단일 선택 라디오 묶음(둘 다 두기·덮어쓰기·더 최신 것만·건너뛰기)과 주 단추 "확인"으로 바꾼다. 헤더의 "취소"는 그대로. 확인을 누르거나 라디오·체크박스에서 Enter를 누르면 지금 고른 결정을 적용한다. Esc는 지금처럼 건너뛰기                                                                                               |
| D2  | 기본 선택은 `newer`("더 최신 것만": 보낼 것이 더 최신일 때만 덮어쓰고 아니면 건너뜀). 처음 포커스는 고른 라디오                                                                                                                                                                                                                        |
| D3  | 폴더 충돌은 덮어쓰지 못한다(기존 D32). 폴더에는 둘 다 두기·건너뛰기만 보인다. 기본/기억한 결정이 덮어쓰기·더 최신 것만이면 폴더 충돌은 둘 다 두기를 미리 고른다(기억한 값 자체는 바꾸지 않는다). 나머지에 적용할 때도 폴더에는 덮어쓰기·더 최신 것만을 보내지 않고 둘 다 두기로 보낸다                                                 |
| D4  | 시트 아래쪽 바닥글, 확인 단추 옆에 "지금 결정 기억하기" 체크박스(ko). 확인 때 켜져 있으면 고른 결정을 기억하고, 다음 시트가 그것을 미리 고른다. 꺼져 있으면 아무것도 기억하지 않고 전에 기억한 값도 잊는다(다음 시트는 더 최신 것만, 기억하기 꺼짐). 켜짐 초기값은 기억한 값이 있으면 켜짐, 없으면 꺼짐. 앱을 다시 켜도 유지(아래 D4a) |
| D4b | 확인 때 기억하는 것은 사람이 누른 결정이다. 폴더 충돌이 미리 고른 둘 다 두기를 다시 눌러도 누른 것으로 친다. 저장된 값이 결정이 아니면(손으로 고친 값, 나중 버전의 이름) 기억이 없는 것으로 본다: 더 최신 것만, 기억하기 꺼짐                                                                                                          |
| D4a | 저장은 렌더러의 기존 설정 저장소 `useSettingsStore`(zustand `persist`, localStorage `ftp-browser-settings`)에 `conflictChoice: ConflictDecision \| null`로 둔다. IPC·DB는 더하지 않는다. 버전은 올리지 않는다(필드 추가뿐, 없으면 `null`)                                                                                              |
| D5  | "나머지 N개에도 똑같이 적용" 체크박스는 그대로(한 배치 안). 선택지 아래, 바닥글 위에 둔다                                                                                                                                                                                                                                              |
| D6  | 더 최신 배지, 두 카드, 포커스 가두기(Tab은 시트 안을 돈다. 라디오 묶음은 고른 하나만 지나간다), 닫을 때 포커스 복원은 그대로                                                                                                                                                                                                           |

새 i18n 키 `conflict.confirm`·`conflict.rememberChoice`·`conflict.choiceLabel`(라디오 묶음의 접근성 이름)을 `en.ts`와 나머지 10개 로케일에 넣는다.
ko의 `rememberChoice`는 "지금 결정 기억하기".

### 기각한 대안

| 대안                                           | 기각 이유                                                                                                                           |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 단추 네 개를 두고 "기억하기"만 더한다          | 기본 선택을 보일 수 없다. 눌러야 적용되는 단추는 "미리 고른 값"을 표현하지 못한다                                                   |
| 기억한 결정이 있으면 시트를 아예 띄우지 않는다 | 사람이 요청하지 않았다. 되돌릴 길(설정 화면)이 없는 숨은 동작이 된다                                                                |
| 기억한 결정을 main의 DB·IPC에 저장한다         | 렌더러 설정은 이미 `useSettingsStore`(persist)에 있다. 새 채널 세 곳 수정이 과하다                                                  |
| 기억하기를 Esc·취소에도 적용한다               | Esc는 건너뛰기, 취소는 보내기 취소다. 결정을 확인한 것이 아니다                                                                     |
| 기억하기를 끄고 확인해도 전에 기억한 값을 둔다 | R3에서 확인: 다음 시트가 다시 체크된 채 예전 결정으로 열려, 끈 체크가 아무 일도 하지 않은 것처럼 보인다. 기억을 지울 다른 길도 없다 |
