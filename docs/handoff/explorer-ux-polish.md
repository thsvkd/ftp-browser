# 핸드오프: 탐색기 UX 다듬기 (좁은 경로 막대 ⋯ 메뉴, 분할 칩, 키보드로 연 메뉴)

split-view R3과 explorer-menu-and-focus에서 "후속"으로 남긴 UX 다섯 가지를 한 번에 고친다. 출처는 `docs/handoff/split-view.md` §15 R3 관찰 1·2·3·5와 그 결함 1의 고침(`492990d`), 그리고 `docs/handoff/explorer-menu-and-focus.md` §11 끝의 "정렬 메뉴 ↔ '…' 메뉴 전환" 후속이다.
`[사용자]` 결정은 사람이 다섯 가지 모두를 하기로 고른 것이다. 이 문서가 그 선택을 구현 단위로 내린 **유일한 입력**이다.
이 문서에 없는 케이스는 완료 범위 밖이다. 케이스를 추가·병합·재해석하지 말 것.

작업 유형(R0): **렌더러 UI 변경**이다. 새 순수 모듈 1개(`lib/pathBarTools.ts`)를 더하고, 순수 함수 1개(`splitLayout.chipSlot`)와 상수를 더한다. 컴포넌트 6개(`PathBar`·`FileFilterMenu`·`Explorer`·`ItemMenu`·`TabStrip`·`SplitOverlay`)와 테스트 하네스 1곳(`explorerTestHarness`의 측정 스텁, §4 함정 1)을 고치고, i18n 키 1개를 11개 로캘에 더한다. main·IPC·DB·공유 타입 변경은 없다.
슬라이스는 셋이다(§8). 슬라이스마다 §6의 테스트를 먼저 세워 RED를 보고 GREEN으로 만든 뒤, 끝으로 실제 앱에서 R3 실측(§9)을 한다.

기준 커밋: `4747d96`(`feat/v1.4-followups`). 아래 줄 번호는 모두 이 커밋에서 읽어 확인했다.

## 2. 핵심 결정 (R1)

`[사용자]`는 사람이 정한 것이고, 나머지는 이 문서가 그 결정을 코드에 대응시키며 근거와 함께 정한 것이다. `미결(권장안 적용)`은 권장안으로 진행하되 사람의 확인이 필요한 것이다(§10에도 모았다).

| X1  | `[사용자]` **경로 막대는 어느 폭에서도 한 줄(52px)이다.** 막대와 도구 묶음에서 `flex-wrap`을 지운다. 들어가지 않는 도구는 막대 오른쪽 끝의 `⋯` 버튼 하나로 접힌다. `⋯`는 무엇이 접혔을 때만 보인다. `--path-bar-h`(`PathBar.tsx:301-303`)는 그대로 둔다(늘 52px이 되지만 바쁨 막대·놓기 테두리가 이미 그 값을 따른다. 지우는 것은 이 변경의 범위가 아니다)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| X2  | **미결(권장안 적용) 접히는 도구와 순서.** 늘 남는 것은 뒤로·위로·조각 상자(경로)·`⋯`이다. 접히는 것은 8개이고, **먼저 접히는 것부터** 정보 → 새 폴더 → 새로 고침 → 앞으로 → 보기 → 정렬 → 필터 → 찾기다(`PATH_TOOL_KEEP`은 이것의 역순). 근거는 "다른 길이 있는가"와 "버튼만 보여 주는 상태가 있는가"다. 앱에 사용 빈도 계측이 없으므로 코드에서 확인되는 대체 경로를 증거로 쓴다. ① 정보: Alt+Shift+P(`AppShell.tsx:116-120`)와 오른쪽 레일의 자기 탭(`RightRail.tsx:60-76`), 상태(정보가 보이는가)도 레일 자체가 보인다. ② 새 폴더: Ctrl+Shift+N(`Explorer.tsx:782`)과 빈 곳 메뉴(`:648-653`), 읽기 전용이면 어차피 비활성이다. ③ 새로 고침: F5·Ctrl+R(`AppShell.tsx:115`)과 빈 곳 메뉴(`Explorer.tsx:655`). ④ 앞으로: Alt+→(`:706`)와 마우스 4번 버튼(`:920`), 뒤로 간 뒤에만 켜진다. ⑤ 보기: 단축키·메뉴가 없지만 지금 보기(그리드·목록)는 내용 자체로 보인다. ⑥ 정렬: 목록 보기에서는 열 머리글이 정렬한다(`ListHeader.tsx:42-48`). 그리드에는 대체가 없고 방향(↑↓)은 버튼만 보여 준다. ⑦ 필터: 대체 경로가 없고, 켜진 개수 배지가 "항목이 숨어 있다"의 유일한 신호다(`FileFilterMenu.tsx:354-357`). ⑧ 찾기: Ctrl+F가 있지만 가장 자주 쓰는 도구이고, 찾는 말이 있으면 지금도 좁은 막대에서 칸을 늘 보인다(`PathBar.tsx:333`)                            |

## 4. 구현 함정

1. **측정 스텁이 모든 도구를 접는다.** 탐색기 테스트는 `stubGridLayout`(`rendererTestUtils.ts:109-160`)으로 모든 요소의 `offsetWidth`·`clientWidth`를 1200으로 둔다(`setupExplorer`, `explorerTestHarness.ts:113`). 그대로면 측정한 도구 하나하나가 막대만큼 넓어 전부 `⋯`로 접히고, 도구 버튼을 이름으로 찾는 기존 테스트(Test-826·944·848·1058·1066 등)가 깨진다. `setupExplorer`가 `stubGridLayout` 뒤에 `offsetWidth`를 게터로 바꿔 `[data-path-measure]` 안의 요소는 **40px**, 나머지는 지금처럼 1200을 돌려주게 하고 `restore`에서 되돌린다. `Crumbs`의 측정 줄은 이 속성이 없으므로 지금처럼 1200이다(Test-826의 "조각마다 1200px" 전제가 그대로다). 이 스텁에서 막대 폭 `W`는 `HTMLElement.prototype.clientWidth`로 정한다(Test-826·944가 이미 그렇게 한다). 측정값이 모두 40이면 `W >= 642`에서 모두 보이고, `W = 400`이면 찾기만 보이고, `W = 300`이면 모두 `⋯`에 들어간다.
2. **측정 줄에 id·이름을 두지 않는다.** 찾기 칸 id(`explorer-filter-<탭 id>`)와 버튼 이름이 둘이 되면 Ctrl+F와 `getByRole`이 엉뚱한 것을 잡는다. 측정 줄은 같은 클래스의 자리표시자(`aria-hidden`, `invisible`, `pointer-events-none`)다.
3. **간격은 함수가 더한다.** 측정한 폭에는 간격을 넣지 않는다. 찾기 칸의 `ml-1`(`PathBar.tsx:413`)은 지운다. 간격(`gap-1.5`)이 이미 띄우고, 남겨 두면 측정값과 실제 자리가 4px 어긋난다. 조각 상자의 `ml-1`은 `CRUMB_MARGIN_PX`로 센다.
4. **접힌 필터의 팝오버.** 트리거가 없으면 `FileFilterMenu`의 `measure`(`:276-293`)가 기준을 잃는다. 기준 요소를 `⋯` 버튼으로 받는다. 바깥 pointerdown 판정이 `⋯`를 바깥으로 치면, `⋯` 메뉴의 "필터" 항목을 누른 pointerdown이 방금 연 팝오버를 닫는다(열림은 click이고 닫힘은 그보다 먼저인 pointerdown이라 순서상으로는 안전하지만, 팝오버가 열린 채 `⋯`를 다시 누르는 경우를 위해 기준 요소를 안쪽으로 친다).
5. **`detail === 0` 판정은 click 처리기 안에서만 한다.** 같은 버튼의 `onKeyDown`에서 따로 Enter를 잡지 않는다(두 번 열린다). jsdom의 `fireEvent.click`과 `new MouseEvent('click')`도 `detail`이 0이라 키보드로 친다. 마우스를 흉내 내는 테스트는 `{ detail: 1 }`을 준다.
6. **다시 마운트는 열림의 정체가 바뀔 때만.** key에 `items`를 넣지 않는다. `Explorer`의 메뉴는 열린 동안 `items`가 매 렌더 새 배열이다(`:1058`). key에 넣으면 렌더마다 다시 마운트되어 포커스와 하위 메뉴를 잃는다. x·y는 열 때만 정해지고 열린 동안 바뀌지 않는다(모든 호출처에서 확인했다).
7. **칩 자리는 무장된 존 안에서만 바뀐다.** 무장이 풀려 흐려지는 동안(`live === null`, `SplitOverlay.tsx:35-43`)에는 마지막 자리를 유지한다. 그렇지 않으면 흐려지는 칩이 위아래로 튄다. 위↔아래 전환은 위치 transition을 걸지 않는다(`top`↔`bottom`은 보간되지 않는다).
8. **Ctrl+F를 올린 뒤에도 AppShell의 넘김은 그대로다.** `AppShell.tsx:121-127`은 Ctrl+L·Ctrl+F를 목록에 넘긴다. 목록의 처리기가 이제 DOM을 찾지 않고 `setSearchOpen(true)`를 부를 뿐이다.

## 5. 기각한 대안

- **지금처럼 줄바꿈 유지** — 사람이 한 줄을 골랐다(X1). 기각.
- **도구 묶음을 가로 스크롤로 두기** — 무엇이 잘렸는지 보이지 않고 키보드로 닿기 어렵다. 기각.
- **고정 폭 표(로캘 무관)로 접기** — 넓은 막대의 라벨 폭이 로캘마다 크게 다르다("Fecha de modificación"). 좁은 막대에서도 필터 배지가 폭을 바꾼다. 기각(X5).
- **들어가는 것은 무엇이든 보이기(앞부분 규칙 없이 빈틈 채우기)** — 폭에 따라 덜 중요한 도구가 보이고 중요한 도구가 숨는 조합이 생기고, 폭을 줄일 때 도구가 뒤섞여 사라진다. 기각(X3).
- **찾기를 절대 접지 않기** — 240·258·280px에서 돋보기(42px)까지 넣으면 조각 상자가 56px 아래로 떨어져 루트 배지와 "…"도 잘린다. 기각(X4·X6).
- **찾는 말이 있으면 칸 대신 강조된 돋보기만 두기(조각 유지)** — 찾는 말이 보이지 않아 왜 목록이 짧은지 알 수 없다. 지금 동작(찾는 말이 있으면 칸을 늘 보임)과도 어긋난다. 기각, 미결 X6의 대안으로 §10에 남긴다.
- **필터를 `⋯` 하위 메뉴(체크 항목)로 옮기기** — 확장자 입력·고급 영역이 있는 대화 상자라 메뉴 항목으로 옮길 수 없다. 같은 팝오버를 `⋯` 아래에 연다(X8). 기각.
- **칩을 늘 위에 두기** — 탭을 탭줄에서 끌어 내리므로 무장되는 순간 포인터가 콘텐츠 위쪽에 있어 바로 겹친다. 기각(X10).
- **무장 중 고스트를 흐리게(또는 숨기게)** — 흐리게 해도 칩 위에 겹쳐 글자가 섞인다. 숨기면 가운데 존(취소)으로 갈 때마다 고스트가 다시 나타나 깜빡이고, 무엇을 끄는지 포인터 옆에서 볼 수 없다. 기각.
- **고스트를 포인터 위쪽으로 옮기기** — 칩이 영역 가운데에 있는 한 포인터를 가운데로 가져가면 고스트의 어느 자리든 칩과 겹친다. 기각.
- **"남는 탭" 칩을 칠한 칩과 같은 `--tx`로** — 대비는 더 높지만 둘의 위계가 사라진다. `--mu`도 AA를 넘는다. 기각(미결 X11).
- **새 토큰(`--chip` 등)을 만들기** — 기존 `--sf`·`--mu`로 두 테마 AA가 된다. 기각.
- **메뉴 버튼마다 `onKeyDown`에서 Enter·Space를 잡아 키보드로 열기** — 버튼의 기본 동작(click)과 두 번 열린다. `detail === 0`이 같은 정보를 준다. 기각(함정 5).
- **`ItemMenu`가 `window.event`로 키보드 여부를 스스로 판단** — 사용이 권장되지 않는(deprecated) 전역이고, 비동기로 여는 `＋`(`await loadPlaces()` 뒤)에서는 이벤트가 이미 끝나 있다. 기각.
- **호출처마다 `ItemMenu`에 메뉴 종류별 key 주기**(§11 첫 선택지) — `PathBar`·`TabStrip` 둘 다 고쳐야 하고 다음 호출처도 같은 함정을 밟는다. M2의 "한 곳에서 막는다"와 어긋난다. 기각(X14).
- **바깥 닫기를 `window` capture 하나로 통합**(explorer-menu-and-focus §5의 후속) — 닫기가 대상 처리기보다 먼저 돌아 "A 닫힘 → B 열림" 순서가 바뀌는 큰 변경이다. 이번 증상은 X14로 풀린다. 기각.

## 10. 위험·미결·후속 과제

**미결(권장안 적용) — 사람 확인 필요**

- **X2 접히는 순서.** 정보 → 새 폴더 → 새로 고침 → 앞으로 → 보기 → 정렬 → 필터 → 찾기. 사용 빈도 계측이 없어 대체 경로와 상태 표시를 근거로 정했다. 다른 안은 "보기를 필터보다 오래 남기기"(보기 전환을 자주 쓰는 사용자)다.
- **X4 경로 칸 예약 160px(바닥 96px).** 그래서 280px 패널에서는 찾기 돋보기도 `⋯`에 들어간다. 다른 안은 "도구 우선(예약 96px 고정)"으로, 280px에서 돋보기가 보이고 조각 상자는 98px(이름이 거의 보이지 않음)이 된다.
- **X6 열린 찾기 칸이 조각 자리를 대신한다.** 좁은 패널에서 찾는 말이 남아 있으면 조각이 보이지 않는다. 다른 안은 "찾는 말이 있어도 칸을 닫고 `⋯`/돋보기에 표시만 남기기"(§5)다.
- **X9 경로 막대 메뉴의 Esc가 연 버튼으로 포커스를 돌려준다.**
- **X11 "남는 탭" 칩의 글자 `--mu`.** 다른 안은 `--tx`(위계 없이 더 진하게)다.
- **X14 전환을 `ItemMenu`의 본문 key로 고친다.** 다른 안은 호출처마다 메뉴 종류별 key다(§5).

**위험**

- **칩이 가운데 선에서 위아래로 바뀐다.** 포인터가 콘텐츠 높이의 가운데를 오가면 칩이 자리를 바꾼다. 히스테리시스는 넣지 않았다(단순함). R3 (d)에서 거슬리면 후속으로 고스트 높이만큼의 띠를 둔다.
- **콘텐츠 높이 148px 미만에서는 겹칠 수 있다.** 최소 창 1024×600에서는 이보다 훨씬 크다고 보지만 R3 (d)에서 잰다.
- **`detail === 0`을 키보드로 본다.** 화면 낭독기가 접근성 API로 누른 버튼, 스크립트의 `.click()`도 키보드로 친다. 이 경우 첫 항목에 포커스가 가는 것은 키보드 사용자와 같은 결과라 해가 없다고 본다.
- **Windows 메뉴 키.** Windows Chromium은 메뉴 키에 keydown 뒤 `contextmenu` 이벤트를 따로 보낼 수 있다. 그러면 키보드로 연 메뉴가 마우스 위치의 빈 곳 메뉴로 바뀔 수 있다(이번 변경과 무관한 기존 경로, `Explorer.tsx:922-929`). macOS R3으로는 볼 수 없다.
- **측정 줄이 DOM을 하나 더 그린다.** 막대마다 자리표시자 11개다. 분할 보기에서도 22개로, 비용은 무시할 만하다고 본다.

**후속 과제(이번 범위 밖)**: 칩 자리 히스테리시스, 탭 메뉴·메뉴 항목의 macOS 단축키 표시(split-view 관찰 4), 탭줄의 넘치는 탭 처리, Windows 검증 호스트에서 메뉴 키·Ctrl+F·`⋯`의 재실측, `--path-bar-h` 정리(한 줄이 된 뒤 쓸모가 줄었다).

#### 관찰 (이번 범위의 결함은 아님, 사람 판단)

1. **위 끝 칩이 경로 막대 위에 뜬다.** `[data-split-root]`가 경로 막대를 포함하므로, 포인터가 아래쪽 절반이면 칩(위에서 24px)이 경로 막대 줄(막대 100~153) 위에 그려진다(`10-chips-light-bottom`). 겹침 보장(X10)과 가독성에는 문제가 없지만 막대 도구를 잠시 가린다.
2. **멈춰 있는 마우스 아래에서 열린 메뉴.** 키보드로 메뉴를 열 때 마우스 포인터가 마침 그 메뉴의 항목 자리에 있으면, 기존 `mouseenter` 고르기가 그 항목을 고른다(Enter로 정렬 메뉴를 열었는데 포인터 아래의 "Folders first"에 포커스). 포인터를 치우면 첫 항목이다. X12와 무관한 기존 동작이다.
3. **좁은 패널의 목록 보기**는 280px에서 이름 열이 보이지 않는다(`09-find-in-slot`, 기존 `LIST_COLS` 고정 열). 이번 범위 밖이다.
4. 240~280px 패널의 조각 상자(98~138px)에는 "… > 0…"처럼 마지막 폴더 이름이 잘린다(X4 예측대로, 이름은 탭 알약에 보인다).
