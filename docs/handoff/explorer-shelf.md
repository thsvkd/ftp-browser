# 핸드오프: 탐색기 개편 — Shelf(V2) 제품화

디자인 랩(`src/renderer/src/lab/`, `npm run lab`)에서 사람이 고른 **V2 "Shelf"**(노브 전부 기본값)를 제품에 옮긴다.
R1 결정은 사람이 내린 6개(§2의 H1~H6)와 그것을 실제 기능에 대응시키며 정한 나머지(D1~)다.
이 문서가 테스트·구현의 유일한 입력이다. 이 문서에 없는 케이스는 완료 범위 밖이다. 케이스를 추가·병합·재해석하지 말 것.

작업 유형(R0): **기능(대규모 UI 교체) + main 전송 기능 3개(폴더 전송, 실패 재시도, 충돌 처리)**.
슬라이스(§13)마다 그 슬라이스의 테스트를 먼저 세워 RED를 보고 GREEN으로 만든다. 끝으로 실제 앱에서 R3 실측(§14)을 한다.

입력 문서:

- 디자인 원본: `src/renderer/src/lab/variants/V2.tsx` + `src/renderer/src/lab/variants/v2/**`(목업 API는 `src/renderer/src/lab/mock/**`).
  **제품 코드는 랩을 import하지 않는다.** 랩 파일은 커밋하지 않은 채로 두고, 사람이 승인하면 마지막에 지운다(H6).
  2026-10-11 승인을 받아 S9에서 지웠다. 이 문서의 랩 경로는 기록으로만 남는다.
- 조사 브리프: `.omc/research/explorer-ux/brief.md` — §1 현재 제품 감사, §2 "정답" 기준선 33개, Concept B.
- 연결 UI(`ConnectBar` + `ServerManagerDialog` + `SavedServersPopover`)는 이미 확정·출시됐다. 그대로 둔다.

## 1. 바꾸는 것

지금 화면은 좌우 2패널(Local | Remote, `react-resizable-panels`)이고 아래에 작업·전송 패널 두 줄과 상태 표시줄이 쌓인다.
Shelf는 한 패널을 크게 쓰고, 탭이 "어느 쪽(내 PC·서버)의 어느 폴더"든 담는다. 옮길 것은 선반에 모아 원하는 탭에서 내려놓는다.

```
┌ Toolbar: ConnectBar · 새로 고침 · [활동 알약 ⬇ 2 ◔] · 설정 · 연결 해제 ──────────────────────┐
├ Sidebar 220 ─┬ TabStrip (알약 탭: 출처 배지 + 이름, ＋) ───────────────────┬ RightRail 288 ┤
│ 내 PC        │ PathBar ‹ › ↑ 출처 › 경로…  ⌕ [사진만] 정렬 ▦☰ 📁+ ⓘ        │ [선반 | 정보] │
│ 서버         │ Explorer (가상화 그리드 4:3 / 리스트)                       │ 선반 더미·목록 │
│ 최근 위치    │                                                             │ [여기로 업로드]│
├──────────────┴─────────────────────────────────────────────────────────────┴───────────────┤
│ StatusBar: 3개 선택 · 24.1 MB · 폴더/파일 합계 · 숨김 N      타일 − ━━ +   ● 서버 · 상태      │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

export type ConflictDecision = 'overwrite' | 'skip' | 'rename' | 'newer'

export interface TransferSendRequest {
  direction: TransferDirection

  /** 대상 경로(결정 키) */

export interface PlanDeps {

  conflicts: Array<TransferConflict & { item: TransferEnqueueItem; renameTo: string }>

export function planDownload(
  deps: PlanDeps,
  remotePaths: string[],
  localDir: string

export function planUpload(
  deps: PlanDeps,
  localPaths: string[],
  remoteDir: string

/** 순수 함수. 결정을 적용해 넣을 항목·건너뛴 항목과, 결정이 없는 충돌을 나눈다 */
export function resolvePlan(
  plan: FolderPlan,
  decide: (conflict: FolderPlan['conflicts'][number]) => ConflictDecision | undefined

  skipped: TransferPlan['skipped']

- `TransferPlan`·`children`·`findRemote`·`outermost`·폴더 지도 로직이 `folderPlan.ts`로 옮겨 간다. `AgentError`·`requireConnected`는 `agentOps.ts`에 남는다.
- `agentOps.download` = `planDownload` → `resolvePlan(plan, () => 'skip')` → 폴더 생성 → `enqueueBatch(..., { exclusive: true })`.
  `agentOps.upload` = `planUpload` → `resolvePlan(plan, () => (overwrite ? 'overwrite' : 'skip'))` → `enqueueBatch`. 건너뛴 사유 문자열은 지금 그대로(`'already exists in the local folder'`, `'already exists on the server'`).
- 다운로드 계획이 만들 로컬 폴더(`plan.dirs`)는 **큐에 넣기 직전에만** 만든다(충돌로 멈춘 첫 호출은 디스크를 건드리지 않는다).

## 8. 구현 함정

1. **옛 UI와 새 UI가 한동안 같이 컴파일된다.** S6에서 `AppShell`이 새 화면으로 바뀌기 전까지 옛 컴포넌트와 그 테스트는 그대로 통과해야 한다.
   `useFtpStore`의 경로 필드를 S8 전에 지우지 말 것. `connect`는 S6에서 "성공하면 `useTabsStore.adoptRemote`"를 **더할** 뿐이다.
2. **원격 썸네일 취소 순서(thumbnail-viewport-priority D14).** 탭 전환도 디렉터리 변경이다. `Explorer`는 `key={activeId}`로 다시 마운트되고,
   `thumbnail:cancelAll`·`gallery:cancelAll`·`useGalleryStore`의 원격 폴더 미리보기 비우기는 활성 탭의 원격 `server|path`가 바뀔 때 **`useLayoutEffect`**로 보낸다. 그래야 새 탭의 첫 배치가 취소 뒤에 나간다(Test-278 이전).
3. **선택은 경로 기준이다.** 옛 스토어는 이름 기준이었다. 타일·행은 `data-path`를 갖고, DOM 조회는 `CSS.escape`를 쓴다(원격 이름에 `"`·`\`가 들어갈 수 있다).
4. **Shift+S와 입력해서 고르기(D29).** 선반 담기는 `e.shiftKey && e.key === 'S'`일 때만이다. 그 밖의 글자(대문자 포함)는 지금처럼 `useTypeAhead`로 간다.
   Space·`\`는 입력해서 고르기에 넣지 않는다.
5. **Ctrl+휠은 네이티브 non-passive 리스너**여야 `preventDefault`가 먹는다(React `onWheel`은 passive). 지금 그리드의 방식을 그대로 옮긴다.
6. **앱 안 드래그의 내용은 스토어(`useDnd`)에 있다.** HTML5 DnD는 문자열만 나른다. 스프링으로 탭이 바뀌면 드래그를 시작한 타일이 언마운트되어
   `dragend`가 React에 오지 않는다. 드래그가 끝난 뒤 첫 마우스 이벤트에서 상태를 지운다(랩 `dnd.ts` 주석). 대상마다 `dragover`에서 `stopPropagation`하고, 루트는 "아무 대상 위도 아님"으로 `over`를 지운다.
7. **앱 안 드래그와 OS 드롭을 구별한다.** `useDnd.items`가 있으면 앱 안, 없고 `dataTransfer.types`에 `Files`가 있으면 OS 드롭(`window.api.getPathForFile`).
8. **계획은 메인 FTP 연결을 쓴다.** 큰 폴더 트리의 계획 동안 탐색 LIST가 줄을 선다. 렌더러는 `transfer:send`를 기다리는 동안 활동 팝오버에 "준비 중" 행(`pendingSends`)을 보이고 UI를 막지 않는다.
9. **결정 키는 대상 경로.** 두 번째 `transfer:send`에 지금 충돌 목록에 없는 키가 와도 무시한다. 새 충돌은 다시 묻는다(Test-765). 시트는 한 호출의 충돌을 다 모은 뒤에만 다시 보낸다.
10. **"더 최신 것만"의 시각 정밀도.** UNIX LIST는 6개월 넘은 파일에 시각 없이 날짜만 준다(자정으로 읽힌다). 엄격히 늦을 때만 덮어쓰므로 같은 날 고친 로컬 파일이 "더 최신"으로 보일 수 있다(§15 위험).
11. **재시도는 새 `WorkItem`이다(D13).** 실패한 항목 객체를 다시 넣지 말 것(구간 항목은 `stopped`라 영원히 `pending`에 머문다). 업로드 재시도는 `created`가 빈 메모로 MKD를 다시 보내므로, 그사이 지워진 폴더도 다시 만든다(Test-761).
12. **에이전트 동기화는 활성 탭만이 아니다.** `ftp:remoteChanged`는 해당 경로의 모든 원격 목록을 무효화하고, 지워진·옮겨진 폴더를 보는 원격 탭은 활성 여부와 관계없이 부모로 간다.
13. **포커스.** 오버레이(메뉴·라이트박스·속성·충돌 시트·팝오버)가 닫히면 연 곳으로 포커스를 돌려준다. 그곳이 사라졌으면 목록(`role="listbox"`)으로.
    탭 전환 뒤 다른 것이 포커스를 갖고 있지 않으면 목록이 포커스를 받는다.
14. **렌더러 테스트는 `window.api`를 목으로 바꾼다.** 새 채널 4개의 허용 목록 누락은 `src/preload/index.test.ts`(Test-770)와 R3로만 잡힌다.
15. **i18n.** `{{count}}`는 복수형 키에만. 다른 수는 `{{number}}`·`{{total}}`. `ru.ts`는 `_few`·`_many`까지. 새 키는 S3가 한 번에 11개 로캘에 넣는다(§10).
16. **랩 코드를 복사하되 import하지 않는다.** 한국어 하드코딩 문자열은 모두 키로 바꾼다. 랩의 `formatBytes`·`formatDate`·`formatSpeed`·`formatDuration`(목업)은 제품 `lib/utils.ts`·`lib/transferRate.ts`로.

## 9. 기각한 대안

- **main에 계획을 보관(계획 id + 만료)** — 두 번째 LIST를 아끼지만 만료·정리·창 닫힘 처리가 생기고, 그사이 바뀐 대상 폴더를 반영하지 못한다. 기각(D8).
- **큐 안에서 작업마다 충돌 상태로 멈추기(랩 목업 방식)** — 큐가 파일마다 대상을 확인해야 하고 배치 중간에 멈춘 작업이 슬롯·연결을 쥔다. `TransferQueue`가 크게 바뀐다. 기각.
- **폴더 단위 충돌** — "덮어쓰기"가 대상 폴더의 다른 파일을 어떻게 할지 정해야 하고 위험하다. 기각(D9).
- **같은 쪽 충돌은 건너뛰고 토스트만** — 사용자가 덮어쓰거나 둘 다 둘 방법이 없고, 전송과 다르게 동작한다. 기각(D32).
- **같은 쪽 보내기를 그대로 두기** — 원격 이동은 서버에 따라 대상을 조용히 바꾸고, 로컬 복사는 늘 덮어쓴다. 기각(D32).
- **렌더러가 실패 작업을 새로 넣어 재시도** — 새 id·새 배치, 업로드 폴더 메모 손실. 기각(D13).
- **쪽마다 스토어 하나(`useFtpStore`/`useLocalFsStore`)로 활성 탭만 표현** — 탭 전환마다 LIST, 같은 쪽 탭 두 개 불가. 기각(D5).
- **원격 탭을 연결된 서버로 조용히 옮기기** — 다른 서버의 경로를 지금 서버에서 연다. 기각(D2).
- **로컬 이동 채널 추가 / 원격 복사(받았다 올리기)** — 랩의 이동/복사 토글을 살리려고 새 기능을 만드는 것이다. 기각(D15, 후속 과제).
- **SUIT·JetBrains Mono 번들** — 패키지가 없고 한글 글꼴이 수 MB. 기각(D4).
- **수동 테마 전환** — H3. 후속 과제였고, D33으로 넣었다.
- **좁은 창에서 레일 접기** — 랩에 없는 새 반응형 코드. 최소 폭을 올린다. 기각(D25).

## 15. 위험과 후속 과제

**위험**

- **범위가 크다.** 렌더러 UI 대부분을 교체한다. S6 전환 커밋 이후 회귀는 §6 표와 R3 (m)로만 걸러진다. S6은 되돌리기 쉬운 단독 커밋으로 둔다.
- **계획이 메인 연결을 오래 쥔다**(함정 8). 수만 개 파일의 폴더를 보내면 그동안 탐색이 느리다. 계획 취소는 이번 범위 밖이다.
- **"더 최신 것만"의 오판**(함정 10). LIST 시각 정밀도·시간대에 따라 틀릴 수 있다. MLSD를 쓰는 서버는 정확하다.
- **GUI 다운로드는 배타적이지 않다**(D12). 계획과 실행 사이 같은 경로에 생긴 파일을 덮을 수 있다(지금 GUI와 같은 수준).
- **같은 쪽 보내기에는 충돌 시트가 없다.** 로컬 복사(`local:copyFiles`)는 덮어쓰고, 원격 이동(RNTO)은 서버에 따라 덮어쓴다. 지금 동작 그대로다.
- **최소 창 폭 1024**(D25). 작은 화면 사용자에게는 변화다.
- **에이전트의 GUI 탐색 표면이 바뀐다.** 영역 이름은 유지하지만(D24) 두 영역이 동시에 있지 않다. 외부 Playwright 스크립트가 있다면 깨질 수 있다.
- **선반 단축키가 랩과 다르다**(D29, S → Shift+S). 사람이 고른 랩과 다른 유일한 조작 변경이다. 한글 초성 입력해서 고르기를 지키려는 것이다.
- **그리드 밖 썸네일의 단건 요청은 탭 전환의 `cancelAll`에 지워질 수 있다**(D30). 그 칸은 다음 마운트 때 다시 요청한다.
- **빈 로컬 폴더는 업로드되지 않는다**(D31). 다운로드는 빈 폴더도 만든다. 비대칭이다.
- **다시 칠하기(D28)는 기계적 치환이라** 대비가 모자란 조합이 남을 수 있다. R3 (j)의 어두운 장면에서 연결 칸·설정 창·서버 관리자를 함께 본다.

**후속 과제(이번 범위 밖)**: 전송 일시 정지·재개(H2), 탭 복원(D23), 로컬 이동·원격 복사(D15), 같은 쪽 보내기의 충돌 시트, 글꼴 번들(D4),
호출 없는 채널 정리(`local:expandForUpload`·`local:selectSaveDirectory`·`local:selectDirectory`·`transfer:enqueue`·`transfer:enqueueBatch`·`drag:start`, D26), 계획 취소, "이미 받은 항목" 표시.

1. (**최종 빌드에서 고쳐짐**) **탭을 바꾸면 스크롤 위치가 복원되지 않는다** ((a)).

| (1) 대상을 비켜 두는 덮어쓰기               | PASS               | 서버 로그 순서는 `RNFR dst/a.txt` → `RNTO dst/.a.txt.k4cnlxb2.old` → `RNFR src/a.txt` → `RNTO dst/a.txt` → `DELE dst/.a.txt.k4cnlxb2.old`이다. 최종 `dst/a.txt`는 SRC-a이고, `.old` 파일은 남지 않는다                                                                                                                                                                                                                                                                                                                |
| (2) 실패 경로                               | PASS               | 시트를 연 뒤 서버에서 원본 `src/f.txt`를 지우고 덮어쓰기를 골랐다. 로그 순서는 `RNFR dst/f.txt` → `RNTO dst/.f.txt.cj7u1rr7.old` → `RNFR src/f.txt` **550** → `RNFR dst/.f.txt…old` → `RNTO dst/f.txt`(되돌림)이다. `dst/f.txt`는 DST-f 그대로 남고 `.old`도 없다. 토스트 "항목 1개를 이동하지 못했습니다 /mv2/dst/f.txt: Permission denied or file/directory not found."가 뜬다(`d32b-fail-toast.png`). 다만 토스트가 실패한 원본이 아니라 대상 경로를 가리키고, 실패한 항목은 선반에 남아 다음 보내기에 다시 섞인다 |
| (3) 서로 다른 폴더의 같은 이름 두 개        | PASS               | `/mv2/a/x.txt`(AX)와 `/mv2/b/x.txt`(BX)를 빈 `/mv2/third`에 내려놓으면 시트 없이 `x.txt`=AX, `x (1).txt`=BX로 둘 다 남는다                                                                                                                                                                                                                                                                                                                                                                                            |

#### D33 실측 (테마 선택)

`build:unpack`과 `smoke:packaged`가 모두 통과했다. FTP 서버 없이 스크래치 user-data-dir로 띄웠고, 설정 창의 "테마" 선택 상자로 바꿨다(시스템 설정 사용·밝게·어둡게). 이 PC의 Windows 앱 모드는 **어둡게**(`AppsUseLightTheme=0`)다.

| 항목                       | 결과 | 근거                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| (1) 어둡게                 | PASS | `prefers-color-scheme: dark`가 true이고 `--bg`=#0f1413, body 배경은 rgb(15,20,19)다(`d33-어둡게.png`)                                                                                                                                                                                                                                                                                            |
| (2) 밝게                   | PASS | 같은 값이 false로 바뀌고 `--bg`=#f4f6f5, body 배경은 rgb(244,246,245)다. 설정 창·선택 상자·스크롤 막대도 밝게 그려진다(`d33-밝게.png`)                                                                                                                                                                                                                                                           |
| (3) 시스템 설정 사용       | PASS | OS가 어둡게이므로 true, `--bg`=#0f1413이다. 저장값은 `"theme":"system"`이다(`d33-system.png`)                                                                                                                                                                                                                                                                                                    |
| (4) 다시 시작해도 유지     | PASS | OS와 반대인 **밝게**를 고른 뒤 `window.close()`로 끄고 같은 user-data-dir로 다시 띄웠다. CDP로 잡은 첫 화면(시작 후 약 0.9초)부터 밝았고(평균 RGB 235,237,233), 어두운 프레임은 잡히지 않았다. 어둡게로도 같은 절차를 밟아 첫 화면부터 어두운 것을 확인했다(`d33-relaunch-light-*`, `d33-relaunch-dark-*`). 다만 창이 페이지가 그려지기 전에 OS 수준에서 잠깐 보이는 깜박임은 CDP로 잡을 수 없다 |
| (5) 토스트·네이티브 컨트롤 | PASS | "경로 복사" 토스트는 어둡게에서 `data-sonner-theme="dark"`·검은 배경, 밝게에서 `light`·흰 배경이다(`d33-dark-toast.png`, `d33-light-toast.png`). 테마 선택 상자의 배경은 어둡게에서 rgb(59,59,59)·글자 rgb(228,236,234), 밝게에서 흰색이다(`color-scheme: light dark`). 열린 드롭다운 목록은 OS 팝업이라 스크린샷으로 확인하지 못했다                                                            |
| (6) 어둡게 + forced-colors | PASS | 어둡게를 고른 상태에서 forced-colors를 에뮬레이션하면 고대비(검정 바탕, 시스템 색 윤곽)로 그려진다(`d33-dark-forced.png`)                                                                                                                                                                                                                                                                        |

실측 메모: 언어 선택 상자에도 "시스템 설정 사용" 항목이 있어, 처음에는 언어 쪽을 바꿨다. 테마 선택 상자를 정확히 집어 다시 확인했고, 언어는 원래 값(시스템)이었다.
