# 핸드오프: 이미 있는 이름으로 바꾸기를 입력하는 즉시 경고

이 문서에 없는 케이스는 범위 밖이다. 새 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

작업 유형(R0): **버그 수정**. RED 테스트를 먼저 세워 실패를 확인한 뒤 GREEN으로 만든다.

---

## 1. 문제 정의

사용자 피드백: _"이름 바꿀 때 같은 폴더가 있는 경우 발생. 같은 이름을 가진 폴더/파일이 있다는 것으로 경고를
수정하던가, 중복된 문자열 입력 시 바로 경고가 뜨게 하던가 해야한다. 후자가 더 좋아 보이긴하다."_

원격에서 같은 폴더에 이미 있는 이름으로 바꾸면 토스트가 `이름을 바꾸지 못했습니다 / Permission denied or
file/directory not found.`라고 한다. 서버는 RNTO를 550으로 거부하고(pyftpdlib: `550 'Is a directory.'`),
`errorClassifier.ts`는 550을 모두 "권한 없음 또는 찾을 수 없음"으로 옮긴다. 550만으로는 "이미 있음"을 다른
실패와 구분할 수 없어 사용자는 원인을 알 수 없다. 로컬은 `LocalFileSystem.rename`이 먼저 막아
`Target already exists: <name>`을 보이지만 그것도 제출한 뒤에야 알 수 있다.

## 2. 결정

| ID  | 결정                                                                                                                                                                                                                                | 이유                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| N1  | 인라인 이름 입력(`InlineRename`)은 입력할 때마다 같은 폴더의 다른 항목 이름과 비교한다. 앞뒤 공백을 뺀 값이 다른 항목 이름과 정확히 같으면 즉시 입력 아래에 `name.taken` 경고(`role="alert"`)를 보이고 입력을 `aria-invalid`로 둔다 | 사용자가 고른 안(입력 즉시 경고). 제출 전에 알 수 있다                                                    |
| N2  | 비교 대상은 그 폴더의 목록 전체다. 숨김 파일 설정·찾기·형식 필터로 가려진 항목도 포함한다. 바꾸는 항목 자신의 원래 이름은 중복이 아니다                                                                                             | 가려졌을 뿐 서버·디스크에는 있어 같은 충돌이 난다                                                         |
| N3  | 경고 중 Enter는 제출하지 않고 편집을 이어 간다                                                                                                                                                                                      | 실패할 것이 확실한 요청을 보내지 않는다                                                                   |
| N4  | 경고 중 바깥 클릭(blur)은 취소다: IPC 없이 원래 이름을 유지하고 오류 토스트도 없다                                                                                                                                                  | blur 뒤에는 편집을 이어 갈 수 없다. 이미 경고를 보았으므로 다시 알릴 필요가 없다                          |
| N5  | 비교는 대소문자를 구분한다                                                                                                                                                                                                          | 원격 서버는 대개 대소문자를 구분한다. 로컬의 대소문자만 다른 충돌은 main 가드가 이미 이름을 들어 거부한다 |

### 검토 후속 결정

| ID  | 결정                                                                                                                                                                                            | 이유                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| N6  | 손대지 않은 원래 이름(앞뒤 공백 포함)은 경고하지 않고, 그대로 Enter를 쳐도 이름 바꾸기를 보내지 않는다                                                                                          | `' a.txt'`와 `'a.txt'`가 함께 있으면 trim한 값이 다른 항목과 같아져 열자마자 경고하고 Enter가 막혔다                                                  |
| N7  | 경고 문구는 클릭을 통과시키고(`pointer-events-none`), 나타날 때 보이도록 스크롤하며, 띄어쓰기 없는 문장도 상자 안에서 줄바꿈한다(`overflow-wrap: anywhere`)                                     | 문구가 아래 항목을 덮어 클릭·끌기를 가로챘고, 맨 아래 항목에서는 화면 밖에 있었으며, ja·zh는 넘쳤다                                                   |
| N8  | 유니코드 정규화(NFC/NFD)만 다른 이름도 N5처럼 미리 경고하지 않는다                                                                                                                              | 원격은 바이트가 다르면 다른 이름이다. 로컬의 이런 충돌은 main 가드가 제출 뒤 이름을 들어 거부한다                                                     |
| N9  | 창 전환으로 생긴 blur(`document.hasFocus()`가 거짓)는 제출도 취소도 아니다. 창으로 돌아오면 입력을 이어 쓴다. 경고 문구는 최소 폭(5rem)을 가져 좁은 리스트 열에서도 세로로 길게 늘어나지 않는다 | 다른 앱에서 이름을 확인하러 다녀오면 입력이 사라졌다. 좁은 열에서 한 글자 폭이 된 문구가 화면보다 길어져 스크롤이 입력을 밀어냈다                     |
| N10 | 편집하던 항목이 그 탭의 목록에서 사라지면(다른 폴더로 이동, 다른 클라이언트·에이전트의 삭제·이름 변경, 목록 오류) 편집을 IPC 없이 닫고, 포커스가 갈 곳을 잃었으면 목록으로 돌린다               | N9로 창이 비활성인 동안 편집이 열려 있을 수 있다. 닫지 않으면 입력이 조용히 사라지고, 같은 경로가 다시 나타날 때 편집이 저절로 열려 포커스를 빼앗았다 |

### 기각한 대안

- **550을 "같은 이름이 있습니다"로 옮기기**: 550은 권한·없음·이미 있음을 함께 뜻해서 다른 실패를 잘못 설명하게 된다.
- **제출 시 목록을 보고 토스트만 띄우기**: 사용자가 원한 것은 입력 즉시 경고다. 입력에서 막으면 토스트가 필요 없다.

| Test-1333 | 숨김 파일 설정으로 가려진 항목(`.secret`)과 찾기로 가려진 항목의 이름도 경고한다                                                                                                                                                                                        |
| Test-1334 | `' a.txt'`와 `'a.txt'`가 있는 폴더에서 `' a.txt'`의 이름 입력을 열면 경고가 없고, 그대로 Enter를 쳐도 이름 바꾸기 IPC를 보내지 않는다(N6)                                                                                                                               |

| Test-1336 | 이름 입력 중 창이 포커스를 잃으면(blur, `document.hasFocus()` 거짓) 경고가 있든 없든 입력이 그대로 남고 이름 바꾸기 IPC를 보내지 않는다. 창으로 돌아온 뒤의 blur는 고유한 이름을 제출한다(N9)                                                                           |
| Test-1337 | 창이 비활성인 동안 편집하던 항목이 목록 새로 고침으로 사라지면 편집이 닫히고(IPC 없음) 포커스는 `body`에 남지 않는다. 같은 이름이 다시 나타나도 편집은 열리지 않는다(N10)                                                                                               |

## 4. 완료 기준

- Test-1330~1337이 수정 전 실패, 수정 후 통과. `npm run typecheck && npm run lint && npm test`.
- 새 키 `name.taken`은 11개 로케일 모두에 있다.
- R3: 실제 앱(pyftpdlib)의 원격 그리드·리스트에서 이미 있는 폴더·파일 이름을 입력하면 즉시 경고가 보이고, Enter는
  아무 요청도 보내지 않으며(서버 로그에 RNFR/RNTO 없음), 고유한 이름은 그대로 바뀐다.
