# 핸드오프: v1.5.0 리뷰 결함 수정 (v1.5.1)

v1.5.0(커밋 `bb9f3bf..05da2e0`, PR #5)을 기능별로 코드 리뷰한 결과 가운데 **긴급·높음·중간 등급**을
고친다(R1에서 인간이 범위를 "중간까지 전부"로 확정). 낮음 등급과 이 문서에 없는 지적은 범위 밖이다.
이 문서에 없는 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

작업 유형(R0): **버그 수정**. 케이스마다 RED 테스트를 먼저 세워 실패를 확인한 뒤 GREEN으로 만든다.

선행 스펙(결정의 출처): `transfer-verb-toggle.md`(V1~V10), `server-connect-activation.md`,
`settings-content.md`, `shelf-floating-remote.md`, `split-server-drop.md`,
`lightbox-video-playback.md`. 아래 결정이 선행 스펙과 충돌하면 **이 문서가 우선**한다.

### 기각한 대안

- **이동을 파일 단위 rename으로 바꾸기**: 볼륨이 다르면 어차피 복사+삭제가 필요하고, F1이 두 경우를 같은 경로로 다룬다.
- **보내기마다 verb를 부분별로 따로 두기(V3 폐기)**: 같은 드롭 안에서 일부만 이동되는 결과를 사용자가 예측할 수 없다.
- **미리보기 취소용 새 IPC 채널**: main이 연결별로 최신 요청만 살리면 채널 없이 같은 효과를 낸다.

## 2. 테스트 케이스

각 테스트에 `// covers: Test-N`을 단다. 번호는 이 문서가 예약한다(origin/main 최대값 1266 다음).

### 이동 안전 (F1~F4)

- **Test-1267** `local:copyFiles` 이동 모드에서 복사 도중 취소하면, 이미 옮긴 파일만 원본에서 사라지고 아직 복사하지 않은 원본 파일은 그대로 남는다.
- **Test-1268** `local:copyFiles` 이동 모드가 끝나면 옮긴 원본 파일과 비게 된 원본 폴더가 지워진다. 원본 폴더에 복사 대상이 아니던 항목(예: 빈 하위 폴더)이 있으면 그 항목과 그 상위 폴더는 남는다.
- **Test-1269** 로컬→로컬 보내기에서 verb가 이동이면 `copyLocal`은 `local:copyFiles`에 이동 모드를 넘기고, `local:deleteBatch`는 부르지 않는다. 복사면 이동 모드를 넘기지 않는다.
- **Test-1270** 전송 이동의 정리는 `completed` 작업의 원본 파일만 지우고, 원본 폴더를 재귀 삭제 대상으로 보내지 않는다. 폴더는 "비었을 때만" 표시로, 깊은 것부터 보낸다.
- **Test-1271** main의 `deleteBatch`(로컬·원격 모두)는 "비었을 때만" 표시가 붙은 폴더가 비어 있지 않으면 지우지 않고 실패로 보고하지 않는다.
- **Test-1272** 두 이동 배치가 같은 플러시에서 완료되고 정리 실행이 겹쳐도, 각 배치의 원본은 정확히 한 번만 지워지고 다른 등록은 사라지지 않는다.
- **Test-1273** 배치를 완료시키는 작업 업데이트가 이동 등록보다 먼저 와도, 등록 직후 정리가 한 번 실행된다.
- **Test-1274** 한 보내기의 두 부분 가운데 A가 끝났을 때 B의 시트가 열려 있으면 A의 원본은 지워지지 않는다. B에서 이동을 고르면 그때 A의 원본이 지워지고, 복사를 고르면 지워지지 않는다.
- **Test-1275** 이동 배치에 취소된 작업이 있으면 원본을 지우지 않고, 모든 작업이 끝난 뒤 등록이 제거된다.

### 연결·스플릿 (F5~F7)

- **Test-1276** 연결된 원격 탭이 활성일 때 사이드바에서 저장 비밀번호가 없는 서버를 더블클릭하면, 진짜 `ConnectBar`가 렌더된 상태에서 그 서버의 비밀번호 입력 칸이 보이고 포커스를 받는다. 연결 시도는 하지 않는다.
- **Test-1277** 같은 상황을 툴바 드롭다운에서 활성화해도 Test-1276과 같은 결과다.
- **Test-1278** 연결되지 않은 서버 행과 끊긴 서버 행의 안내 문구가 클릭이 아니라 더블클릭/Enter로 연결한다고 말한다(en 기준). 11개 로케일의 해당 키가 en과 같은 뜻으로 바뀌었는지는 리뷰로 확인한다.

3. 새 IPC 채널 없음. i18n 키 추가 없음(문구 수정만).
4. `stryker.config.json`의 `mutate`를 이번 변경 라인으로 재지정하고 break 70을 넘는다.
5. R3(실기기, 사람이 확인): 로컬 폴더 이동 중 취소 → 남은 원본 확인 · 연결된 탭에서 비밀번호 없는 서버 더블클릭 · 서버 두 개 연속 드롭 · 선반 띠와 전송 안내 알약이 동시에 보임 · 큰 원격 영상 열고 빠르게 넘기기.

### 테스트 케이스

- **Test-1298** 원격 미리보기가 메인 클라이언트로 폴백해 진행 중일 때 새 요청이 와도 그 다운로드는 끝까지 진행되고 메인 연결이 닫히지 않는다.
- **Test-1299** 이동 배치의 작업 하나가 실패한 뒤 재시도로 완료되면 그때 원본이 지워진다.
- **Test-1300** 이동 배치의 작업이 완료 목록 지우기로 모두 사라지면 등록이 제거되고 아무것도 지워지지 않는다.
- **Test-1301** 이미 그 폴더에 있는 선반 항목을 그 폴더에 놓으면 선반에서 빠진다.
- **Test-1302** "비었을 때만" 폴더가 이미 없거나(ENOENT) 지울 수 없어도(EPERM) 배치는 성공하고 나머지 대상은 처리된다.
- **Test-1303** 로컬→로컬 이동에서 빈 폴더 원본은 대상에 같은 이름의 빈 폴더로 생기고 원본은 사라진다.
- **Test-1304** 로컬→로컬 이동은 중첩 폴더를 깊은 것부터 비워 원본 폴더까지 지우고, 원본 폴더의 부모는 비게 되어도 지우지 않는다.
- **Test-1305** `FtpFileOperations.deleteEmptyDirectory`는 메인 클라이언트에서 RMD(`removeEmptyDir`)만 쓰고 삭제 변경 이벤트를 낸다.
- **Test-1306** 툴바 입력 모드에서 포커스가 툴바 밖으로 나가면 연결된 표시줄로 돌아간다.
- **Test-1307** 연결되지 않은 사이드바 행에서 Enter를 누르면 그 행이 선택된다. 선택 표시는 유효한 ARIA 속성(역할 포함)으로 노출된다.
- **Test-1308** OS 드래그 중 창 안 좌표에서 `relatedTarget` 없는 `dragleave`가 오면 띠는 남고, 창 밖 좌표에서 오면 사라진다.

R3에 추가: 접속 수가 1인 서버에서 라이트박스 영상을 빠르게 넘겨도 목록 탐색이 끊기지 않는지, 실제 Chromium에서 OS 파일을 끌어 자식 요소 경계를 넘나들어도 띠가 깜박이지 않는지.
