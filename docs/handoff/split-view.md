# 핸드오프: 탭 드래그 분할 보기(Split view)

탭을 아래로 끌어 콘텐츠 영역의 왼쪽·오른쪽 절반에 놓으면 두 탭을 나란히 보는 **분할 보기**를 만든다.
R1 결정은 사람과 합의한 `.omc/plans/explorer-v2-decisions.md` §F(이 문서에서 F1~F16)와, 그것을 코드에 대응시키며 정한 나머지(P1~)다.
이 문서가 테스트·구현의 유일한 입력이다. 이 문서에 없는 케이스는 완료 범위 밖이다. 케이스를 추가·병합·재해석하지 말 것.

작업 유형(R0): **기능(렌더러 UI·상태 확장)**. main·IPC 변경 없음. 썸네일·폴더 미리보기 채널의 `viewerId` 인자는 `multi-connection.md` §4.2·§4.3(그 스펙의 S4, 커밋 `06a6902`)이 바꾼 모양을 그대로 쓴다. 구현된 계약(`src/main/ipc/thumbnailHandlers.ts:50-76`, `galleryHandlers.ts:82-107`):

- `thumbnail:requestBatch(conn, viewerId, requests)` → `IpcResult<string[]>`. 그 `(conn, viewerId)`의 직전 배치만 교체한다(`ThumbnailQueue.requestBatch(viewerId, …)`, `ThumbnailQueue.ts:114`). `conn`의 세션이 없으면 실패 값(`sessionIpcError`).
- `thumbnail:cancelAll(conn | null, viewerId)` → `IpcResult<void>`. **`null` = 모든 세션**에서 그 뷰어를 취소한다(`sessionsOf`, `thumbnailHandlers.ts:97-101`). 세션이 없는 키면 아무것도 안 하고 성공.
- `gallery:remoteFolderPreview(conn, { remotePath, viewerId })` → `IpcResult<RemoteFolderPreview | null>`. 같은 폴더를 기다리는 뷰어들은 진행 중 요청 하나를 공유한다(소유 뷰어 집합, `RemoteGalleryPreviewQueue.ts:59-65`).
- `gallery:cancelAll(conn | null, viewerId)` → `IpcResult<void>`. `null`의 뜻은 위와 같다. 그 뷰어를 소유에서 빼고 소유가 빈 대기 항목만 거절한다(`RemoteGalleryPreviewQueue.ts:93-112`).
- `viewerId`가 1~64자 문자열이 아니면 네 채널 모두 `{ success: false, error: 'Invalid viewer id.' }`(`isViewerId`, `thumbnailHandlers.ts:89-94`). `'left'`·`'right'`는 맞는다.

이 문서는 그 자리에 단일 보기 상수 `MAIN_VIEWER`(= `'left'`, `src/shared/connKey.ts:8`) 대신 패널 id를 넣을 뿐이다(P2).
슬라이스(§12)마다 그 슬라이스의 테스트를 먼저 세워 RED를 보고 GREEN으로 만든다. 끝으로 실제 앱에서 R3 실측(§13)을 한다.

**코드 기준 갱신(커밋 `6bffb14`, `feat/explorer-v2`)**: 이 문서는 explorer-menu-and-focus·shelf-os-drop·collapsible-sidebars·file-category-filter·multi-connection 구현 **전에** 썼다. 다섯 스펙이 들어온 코드에 맞춰 코드 포인터(파일:줄)·구현된 계약·§4 감사표를 고쳤다. 결정(F·P·Q)·테스트 케이스의 뜻·번호는 바꾸지 않았다. 갱신에서 새로 드러나 권장안을 적용한 것은 Q6 하나이고(§2 미결), 그 케이스로 Test-1128을 더했다.

## 1. 바꾸는 것

지금은 활성 탭 하나만 그린다(`Explorer.tsx:133-136`, `key={tab.id}`). 분할 보기는 탭줄 하나를 공유하면서 콘텐츠 영역에 탭 두 개를 좌우로 그린다.

```
├ TabStrip:  (A) (B) [ C ┃ D ] (E)  ＋        ← 분할 짝은 묶음 알약 하나. 활성 반쪽 강조
├────────────────────────────────┬┬────────────────────────────────┤
│▔▔▔▔▔▔ 2px --ac (활성 패널만) ▔▔▔▔│││ PathBar (비활성: 글자 --mu)     │
│ PathBar ‹ › ↑ 경로 · 보기·정렬·필터 │││                                │
│ 목록 C (data-pane="left")        │││ 목록 D (data-pane="right")      │
│                                  │││                                │
└──────────────── ratio ───────────┴┴── 구분선(최소 패널 280px) ───────┘
StatusBar · Shelf 대상 · 정보 패널 · 사이드바 강조 · 전역 단축키 = 활성 패널의 탭
```

탭 드래그(포인터 이벤트):

```
pointerdown(탭) ─4px─▶ dragging ─┬─ y ≤ 탭줄 하단+16 : reorder (삽입 표시선, 놓으면 순서 변경)
                                 └─ y > 탭줄 하단+16 : split  (탭줄 하단선 위로 오면 reorder로 복귀)
split: 존(좌 33% · 가운데 34% · 우 33%)에 60ms 머무르면 오버레이 → 놓으면 분할. 가운데·Esc·창 밖 = 취소
```

## 3. 상태 모델과 화면 구조

### 3.1 스토어 API (`stores/useTabsStore.ts`, 확장)

```ts
export type PaneId = 'left' | 'right'
export interface Split {
  leftId: string
  rightId: string
  /** 왼쪽 패널 비율 0~1. 그릴 때 clampRatio로 자른다(P8) */
  ratio: number
}

interface TabsStore {
  // …지금 필드·동작 그대로
  split: Split | null
  /** 탭 `id`를 `beforeId` 앞으로(null이면 끝). 짝의 반쪽이면 짝 전체가 움직인다. 짝 사이는 짝 뒤로(P4) */
  moveTab: (id: string, beforeId: string | null) => void
  /** 드래그 놓기·"오른쪽에 분할"·⌘\의 공용 규칙(§3.2) */
  placeInPane: (id: string, pane: PaneId) => void
  unsplit: () => void
  /** 좌우 바꾸기: leftId·rightId와 탭 순서를 바꾼다. ratio·activeId는 그대로 */
  swapPanes: () => void
  /** P5 */
  toggleSplit: () => void
  /** 0~1로 자른 값을 저장한다 */
  setSplitRatio: (ratio: number) => void
  goBack: (tabId?: string) => void // P13. 없으면 활성 탭
  goForward: (tabId?: string) => void
  goUp: (tabId?: string) => void
}

/** 보이는 패널. 분할이 보이면 [left, right], 아니면 [{ pane: 'left', tabId: activeId }], 탭이 없으면 [] */
export function visiblePanes(s: TabsState): Array<{ pane: PaneId; tabId: string }>
export function activePane(s: TabsState): PaneId
```

`closeTab(id)` 변경: `id`가 짝의 반쪽이면 `split = null`, 닫은 탭이 활성이었으면 **짝의 다른 반쪽**이 활성이 된다(지금 규칙대로면 짝 뒤의 탭이 활성이 된다). 짝 밖의 탭을 닫으면 지금 규칙 그대로(Test-783), 분할은 유지.
`split`은 persist하지 않는다(Q2). multi-connection.md의 "화면에 보이는 탭"(자동 연결, MC12)은 `visiblePanes`의 탭들이다. 구현은 `TabExplorer`마다 `useAutoConnect(tab)`(`Explorer.tsx:116-127`, deps `[tab.id, server]`)을 부르므로 `visiblePanes`가 그리는 패널이 곧 그 탭들이고, 이 문서가 따로 연결할 것은 없다(§4 23행).

### 3.2 `placeInPane(id, pane)` 규칙

1. 탭이 2개 미만이면 아무것도 안 한다(F3).
2. **분할이 보이면**(`activeId ∈ 짝`, F10 "좌/우 절반 = 해당 패널의 탭 교체". 드래그에서 `pane`은 `zoneFromPoint`의 `left`/`right` 존이고 `center` 존이면 이 함수를 부르지 않는다 — P15·§5):
   - `id`가 이미 `pane`에 있으면 아무것도 안 한다.
   - `id`가 짝의 다른 반쪽이면 `swapPanes()` 하고 `activeId = id`.
   - `id`가 짝 밖이면 **교체**: `pane`에 있던 탭 Y와 `id`가 `tabs`에서 자리를 맞바꾸고, `split[pane]`이 `id`가 된다. `ratio` 유지, `activeId = id`. Y는 일반 탭이 된다.
3. **분할이 안 보이면**: 숨은 짝이 있으면 먼저 푼다(Q3). 짝 `P = splitPartner(순서, activeId, id)`. `id`를 순서에서 빼 `P` 바로 뒤(`pane === 'right'`) 또는 바로 앞(`'left'`)에 넣고, `split = { leftId, rightId, ratio: 0.5 }`, `activeId = id`.

### 3.3 순수 함수 (`lib/splitLayout.ts`, 신규)

```ts
export interface Rect {
  left: number
  top: number
  width: number
  height: number
}
export type Zone = 'left' | 'center' | 'right'

/** F5·F8. rel = (x - left) / width. rel < 0.33 → left, rel > 0.67 → right, 그 사이(양 끝값 포함) → center.
 *  rect 밖(x < left, x > left+width, y < top, y > top+height)이거나 width·height ≤ 0이면 null. 테두리는 안쪽이다 */
export function zoneFromPoint(rect: Rect, x: number, y: number): Zone | null
/** F6·Q5. 오버레이가 칠할 영역(안쪽 여백 6px는 CSS가 더한다). ratio가 null(분할이 안 보임)이면 존 쪽 절반,
 *  아니면 그려지는 비율 r = clampRatio(ratio, rect.width) 기준 그 패널(left: 0~r, right: r~1). top·height는 rect 그대로 */
export function overlayRect(rect: Rect, zone: 'left' | 'right', ratio: number | null): Rect
/** F4 히스테리시스. reorder → split은 y > stripBottom + 16일 때만, split → reorder는 y < stripBottom일 때만 */
export function dragModeFor(
  prev: 'reorder' | 'split',
  y: number,
  stripBottom: number
): 'reorder' | 'split'
/** P8. min = 280 / width. min ≥ 0.5(폭 ≤ 560)면 0.5, 아니면 ratio를 [min, 1 - min]로 자른다 */
export function clampRatio(ratio: number, width: number): number
/** 순서 변경 삽입 위치: 단위(탭 또는 묶음 알약)의 가운데 x 목록에서 x보다 왼쪽인 개수 */
export function insertionIndex(mids: readonly number[], x: number): number
/** P3. dragged ≠ active → active. dragged = active → 순서상 다음, 없으면 앞. 탭이 1개면 null */
export function splitPartner(
  order: readonly string[],
  activeId: string,
  draggedId: string
): string | null
```

상수(`lib/explorerLayout.ts`에 추가): `TAB_DRAG_START_PX = 4`, `SPLIT_ENTER_PX = 16`, `SPLIT_DWELL_MS = 60`, `SPLIT_EDGE = 0.33`, `PANE_MIN_PX = 280`, `SPLIT_FADE_MS = 150`, `SPLIT_SWITCH_MS = 100`(F7의 70~120 안), `SPLIT_SETTLE_MS = 200`(CSS는 collapsible-sidebars.md의 `--pane-anim: 200ms`를 쓴다).

오버레이(`SplitOverlay`) 겉모습(F6·F7):

- 칠하는 영역: `overlayRect(콘텐츠 rect, 존, 분할이 보이면 ratio 아니면 null)` — 분할이 안 보이면 콘텐츠의 왼쪽 또는 오른쪽 **절반**, 보이면 교체될 **패널 영역**(Q5). 콘텐츠 기준 `left`·`width`를 인라인 스타일로 둔다. 안쪽 여백 6px, `border-radius: 12px`, 배경 `color-mix(in srgb, var(--ac) 14%, transparent)`, `box-shadow: inset 0 0 0 2px var(--ac)`. `data-zone="left|right"`.
- 칠한 영역 가운데 칩: `SourceBadge`(끄는 탭의 쪽) + P15 문구. 반대쪽 가운데 칩: `split.remaining`, `opacity: .7`.
- 나타남 `opacity` 150ms ease-out, 좌↔우 전환은 위치 `transition` 100ms ease-out. `@media (prefers-reduced-motion: reduce)`에서 둘 다 끔. 전체 `pointer-events: none`, `aria-hidden`.
- 놓아서 새 분할이 생기면 두 패널의 `flex-basis`가 100%/0에서 비율로 200ms ease-out 전환(`data-entering`, 한 번만). 동작 줄이기에서 끔.

묶음 알약(F1): `role="group"`(이름 `split.pair`) 안에 반쪽 두 개, 각각 지금 `TabPill`과 같은 `role="tab"` 버튼(+ 닫기 버튼, 파일 드래그 놓기 대상·스프링 그대로). `aria-selected`는 활성 탭인 반쪽만. 분할이 보이면 활성 반쪽은 지금의 활성 알약 모양, 다른 반쪽은 보통 글자. 짝이 숨으면 두 반쪽 모두 비활성 모양. 반쪽 사이 1px 구분선.

## 8. 구현 함정

1. **`activeId` 불변식.** 분할이 보이는 동안 `activeId`는 짝의 한쪽이다. `split`을 바꾸는 모든 동작(§3.1)이 끝에서 이 불변식과 "짝은 인접"(P4)을 지키는지 스토어 테스트가 확인한다. `activeId`만 바꾸는 `activate`·`cycleTab`·`openTab`·`showInTab`은 `split`을 건드리지 않는다(보이는지 여부가 P14로 바뀔 뿐).
2. **HTML5 파일 드래그와 탭 포인터 드래그를 섞지 않는다.** 탭 버튼은 `draggable`이 아니다(지금도 아니다). 탭 드래그 중 `useDnd`를 건드리지 않고, 파일 드래그(`useDnd.items`) 중에는 탭 pointerdown이 오지 않는다. 탭의 파일 놓기 대상·스프링(`TabStrip.tsx:26-29`)은 묶음 반쪽에도 그대로 붙는다.
3. **활성화는 capture 단계에서.** `onPointerDownCapture`가 먼저 `activate`해야 같은 pointerdown/click의 목록 처리(선택·마퀴)가 활성 패널 기준 단축키와 어긋나지 않는다. 스토어 `set`은 동기라 같은 이벤트 안의 `getState()`가 새 값을 본다.
4. **스프링·놓기는 pointerdown 없이 일어난다**(P13). 패널 안 `navigate`·`goBack` 등은 **모두** 탭 id를 넘긴다. 탭 id 없는 호출이 패널 컴포넌트에 남지 않게 `grep -n "navigate(\|goBack(\|goForward(\|goUp(" src/renderer/src/components/explorer`로 확인한다.
5. **DOM 노드를 옮기지 않는다**(P10). 배열 순서를 바꿔 렌더하면 React가 노드를 옮기고 스크롤이 0이 된다. 렌더 순서는 고정하고 `style.order`만 바꾼다.
6. **두 패널이 같은 폴더**: id·놓기 키·`[data-path]` 조회 세 가지를 모두 패널 범위로(P9). 테스트(1061·1062)가 같은 폴더를 두 패널에 연다.
7. **썸네일 취소 순서**(thumbnail-viewport-priority D14, explorer-shelf 함정 2)는 패널마다 지킨다: 취소는 layout effect, 새 배치는 passive effect. `viewerId`가 바뀌면(분할 해제로 오른쪽 탭이 왼쪽 단일 패널이 됨) 옛 viewer 취소 → 새 viewer 배치 순서. 그때 사라지는 왼쪽 패널의 `'left'` 취소(§4 17행 (b))도 layout 정리라, React가 같은 커밋에서 passive effect(새 `'left'` 배치)보다 먼저 돌린다 — 새 배치가 옛 패널의 취소에 지워지지 않는다(Test-1064 ④가 호출 순서로 확인).
8. **jsdom 30**: `PointerEvent`(clientX·clientY·pointerId)는 있고 `setPointerCapture`는 없다. 레이아웃이 없어 `getBoundingClientRect`가 0이므로 테스트는 탭줄·`[data-split-root]`·구분선 rect를 고정한다. `matchMedia`가 없다(동작 줄이기는 CSS 미디어 쿼리로만 처리하고 JS로 읽지 않는다).
9. **⌘\\ 자판**: `key`가 `'₩'`(macOS 한국어)·`'¥'`(JIS)일 수 있다. `code === 'Backslash'`도 본다(P5). Windows 한국어 자판은 `key === '\\'`다.
10. **드래그 뒤 click**: 드래그로 끝나면 같은 버튼에 click이 온다. 활성 탭을 바꾸지 않도록 한 번 무시한다(P16). 드래그 없이 끝난 pointerup은 지금처럼 click으로 활성화한다.
11. **macOS 앱 메뉴의 Cmd+W**(`appMenu.ts`의 `role: 'close'`)는 창을 닫는다. 이번 범위가 아니다(지금 동작 그대로).

## 9. 기각한 대안

- **HTML5 DnD로 탭 끌기** — 파일 드래그 payload·`dragover` 전파 규칙(`useDnd`)과 섞이고, `setDragImage`로는 존 오버레이·히스테리시스를 매끄럽게 못 한다. decisions F4가 pointer events로 정했다.
- **활성 패널을 별도 필드로 저장** — `activeId`와 어긋날 수 있고, F14의 다섯 대상을 모두 고쳐야 한다. 기각(P1).
- **패널마다 탭줄** — decisions F1(탭줄 하나 공유).
- **분할 중 다른 탭 클릭 = 활성 패널 교체** — Q1 참고.
- **분할·비율 복원** — Q2 참고.
- **구분선에 `useResizableSidebar` 재사용** — 그 훅은 px 폭·접힘·snap이다. 비율 하나와 더블클릭만 필요하다(P8).
- **`react-resizable-panels` 다시 쓰기** — package.json에 없고(decisions §D) 패널 두 개의 비율 하나에 과하다.
- **창이 좁으면 사이드바 자동 접기** — collapsible-sidebars.md의 동작을 바꾼다. Q4.

- **폴더 미리보기 깜빡임**(P17). 같은 서버 두 패널에서 한쪽이 이동하면 다른 쪽 폴더 타일이 다시 요청되는 동안 글리프로 바뀔 수 있다(main 캐시 적중이면 왕복 한 번).
- **정보 패널의 폴더 미리보기**는 패널 밖이라 기본 뷰어 `'left'`다(P2). 왼쪽 패널이 이동하면 그 대기 요청이 취소될 수 있는데, 지금 단일 보기에서도 이동이 모든 대기 미리보기를 취소하므로 같은 동작이다. 바꾸지 않는다.
- **에이전트의 GUI 표면**: 분할 보기에서 영역 이름이 바뀐다(P12). 단일 보기는 그대로다.
- **macOS Cmd+W**는 창을 닫는다(함정 11, 지금 그대로).
- **패널의 DOM 순서 ≠ 화면 순서**(P10의 대가). 두 패널은 탭을 만든 순서(`tab<N>`의 N)로 렌더하고 좌우는 CSS `order`로만 정한다. 좌우 바꾸기 뒤나 오른쪽 탭이 먼저 만들어졌으면 Tab 키 순서·낭독 순서가 오른쪽 패널부터다(WCAG 2.4.3·1.3.2). F6(§4 지역)은 `data-pane`으로 고르므로 화면 순서를 따른다. DOM을 옮기면 스크롤·포커스를 잃어 받아들인 대가이고, R3 (i)에서 Tab 순서를 함께 본다.
- **묶음 알약의 `role="group"`**(§5, Test-1071). WAI-ARIA 1.2의 `tablist`가 소유할 요소는 `tab`뿐이라 axe가 `aria-required-children`으로 볼 수 있고, 화면 낭독기가 반쪽 탭의 위치·개수를 다르게 셀 수 있다. 스펙의 결정이라 그대로 두고, R3 (i)에서 낭독 결과를 확인해 문제가 되면 `role="presentation"` + 반쪽의 `aria-describedby`(`split.pair`)로 바꾸는 것을 사람과 정한다.

**리뷰 뒤 보완**(케이스 번호는 그대로, 해당 케이스의 테스트에 회귀 확인을 더했다)

- **메뉴는 한 번에 하나**(§4 18행, Test-1069). 항목·빈 곳·탭의 우클릭은 전파를 막는다. 막지 않으면 같은 패널(또는 탭줄)에 이미 열린 메뉴가 그 우클릭을 바깥 우클릭으로 보고 방금 연 메뉴를 닫아, 메뉴가 열린 채 다른 항목·탭을 우클릭하면 아무 메뉴도 남지 않았다. 다른 패널·탭줄의 메뉴는 `ItemMenu`가 열릴 때 window에 보내는 `itemmenu:open`을 듣고 닫히며, 그때 `onClose('replaced')`라 연 쪽은 자기 목록으로 포커스를 되돌리지 않는다(되돌리면 P7로 그 패널이 다시 활성이 된다).
- **탭 메뉴 포커스**(P6, Test-1072). 메뉴를 열 때 포커스가 있던 곳을 기억해, 닫히며 포커스가 body·메뉴 안에 남으면 그리로(없으면 활성 탭으로) 돌려준다. "오른쪽에 분할"은 그 뒤 `placeAndFocus`가 목록으로 옮긴다.
- **활성 반쪽 닫기의 포커스**(Test-1074). 포커스가 있던 활성 반쪽을 닫으면 다른 반쪽은 이미 마운트돼 있어 마운트 때의 포커스 규칙(함정 13)이 돌지 않았다. 그 규칙을 패널이 활성이 될 때도 돌린다.
- **취소한 탭 드래그 뒤의 click**(P16·함정 10, Test-1078). Esc·blur로 취소해도 버튼은 눌려 있고 탭 버튼이 포인터를 캡처해, 손을 떼면 그 버튼에 click이 와 활성 탭이 바뀌었다. 취소한 드래그는 다음 pointerup의 click까지 무시한다(그 전에 키를 누르면 푼다). 창 밖 판정은 순서 변경 모드에도 적용해 표시선을 지우고 놓아도 순서를 바꾸지 않는다(F9).
- **오버레이 좌↔우 전환**(F7, Test-1077). 무장이 풀릴 때마다 오버레이를 내렸다 다시 그려 위치 transition이 돌 수 없었다. 분할 모드로 끄는 동안 한 번 무장된 뒤로는 마운트된 채 마지막 존 자리에서 흐려지고, 다른 존에서 다시 무장되면 같은 요소가 옮겨 간다. "남는 탭" 칩도 같이 나타나고 흐려진다.
- **구분선 끌기의 끝**(Test-1068). `pointerup`·`pointercancel`에 더해 window `blur`와 구분선의 `lostpointercapture`에서도 끝낸다(끄는 중 Alt+Tab).
- **폴더 미리보기의 낡은 답**(P17, Test-1064). 대기 중인 미리보기를 좌우 바꾸기(또는 같은 서버 다른 패널의 이동)가 취소하면 `clearRemote`로 항목이 지워져 타일이 새 뷰어로 다시 요청하는데, 그보다 먼저 온 옛 요청의 `Cancelled`가 오류를 써 타일이 글리프로 굳었다. 요청은 자기가 쓴 대기 항목이 그대로일 때만 답을 쓴다.

#### 관찰 (이번 범위의 결함은 아님, 사람 판단)

1. **끄는 고스트가 오버레이 칩을 가린다.** 고스트는 포인터 오른쪽 아래에 붙고 칩은 칠한 영역 가운데라, 포인터를 패널 가운데쯤(사람이 대개 놓는 곳)에 두면 "오른쪽에 분할 · <이름>"의 이름 부분이 고스트에 덮인다(`a2-overlay-right`·`a2-overlay-left`). 칩을 위로 올리거나 무장 중에는 고스트를 흐리게 할지 정한다.
2. **"남는 탭" 칩(불투명도 .7)이 사진 위에서 잘 안 읽힌다.** 어둡게 테마에서 빨간 썸네일 위의 "남는 탭: inbox"는 글자 대비가 낮다(`j-overlay-dark-motion-left`). F6의 .7은 결정이므로 그대로 두었다.
3. **좁은 패널의 경로 막대가 두세 줄이 된다**(결함 1의 고침). 280px 이하에서는 정보 버튼이나 도구 묶음 일부가 셋째 줄로 내려가 목록이 그만큼 짧아진다(258px에서 133px). 넘치는 도구를 메뉴 하나로 접는 방식이 나은지 사람이 본다.
4. **탭 메뉴의 단축키 표시가 macOS에서도 `Ctrl+\`다**(P6·Test-1072의 문구). 실제 키는 ⌘\\도 된다. 사이드 패널 토글은 macOS에서 `⌘B`로 보인다.
5. **키보드로 연 메뉴는 첫 항목이 아니라 메뉴에 포커스가 있다**(explorer-menu-and-focus의 `ItemMenu` 동작). Shift+F10 뒤 Enter만으로는 아무것도 안 되고 ↓를 먼저 눌러야 한다.

**사람에게 남는 확인**: 실제 ⌘Tab/Alt+Tab으로 끄는 중 창을 떠나는 취소(b), Windows 검증 호스트의 Ctrl+\\, 묶음 알약 `role=group`과 좌우 바꾸기 뒤 Tab 순서의 화면 낭독(§14 위험 두 항목), 위 관찰 1~3의 디자인 판단(고친 두 줄 경로 막대의 모양 포함).
