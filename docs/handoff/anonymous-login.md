# 핸드오프: 서버 관리창의 명시적 익명 로그인

작업 유형(R0): **기능 추가**. 케이스마다 RED 테스트를 먼저 세워 실패를 확인한 뒤 GREEN으로 만든다.
이 문서에 없는 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

## 0. 지금 상태

익명 로그인은 이미 **암묵적으로** 동작한다. 사용자 이름이 비었거나 `anonymous`(대소문자 무관)면
`anonymous` / `anonymous@`로 로그인한다(`useServerStore.ts` `connect`, `ftpHandlers.ts` `ftp:connect`).
저장할 때 익명 사용자는 `''`로, 기본 비밀번호 `anonymous@`는 저장하지 않는다(`servers.ts`
`recordConnection`). 서버 관리창(`ServerForm.tsx`)에서 이를 알려 주는 것은 사용자 이름 칸의 자리표시
`anonymous`뿐이다. 툴바(`ConnectBar.tsx`)는 주소 한 칸(`user@host:port`)이라 `user@`가 없으면
익명이고 비밀번호 칸도 사라진다.

R1에서 인간이 범위를 "명시적 '익명' 체크박스"로 정했다(익명 비밀번호 설정은 범위 밖).

### 기각한 대안

- **툴바에도 익명 토글** — 주소 한 칸 구조에서 `user@`를 지우는 것과 같은 일을 두 곳에서 하게 된다. 기각(AN1).
- **`ServerDraft`·`FtpServer`에 `anonymous` 필드 추가** — 저장 형식은 이미 빈 사용자 이름이 익명이다. 새 필드는 DB·IPC·MCP까지 번진다. 기각(AN2·AN3).
- **익명 비밀번호(이메일) 설정** — R1에서 범위 밖으로 정했다.

## 2. 테스트 케이스

각 테스트에 `// covers: Test-N`을 단다. 번호는 이 문서가 예약한다(origin/main 최대값 1308 다음, 1309~1315. 리뷰 후속은 1391~1395).
모두 `src/renderer/src/components/server/ServerManagerDialog.test.tsx`(jsdom)에 둔다.

- **Test-1309** 사용자 이름이 빈 저장 서버를 고르면 "익명으로 로그인" 체크박스가 체크돼 있고, 사용자 이름·비밀번호 칸이 `disabled`다. 사용자 이름이 `me`인 저장 서버를 고르면 체크가 풀려 있고 두 칸이 켜져 있다. 새 서버 폼은 체크된 채 열린다(AN2).
- **Test-1310** 사용자 `me`·저장 비밀번호가 있는 서버에서 체크하면 사용자 이름 칸이 비고 두 칸이 `disabled`, "저장된 비밀번호 제거" 버튼이 사라진다. 저장하면 `ftp:saveServer` 인자의 `username`이 `''`이고 `password`가 `''`다(저장 비밀번호 삭제, AN3).
- **Test-1311** 사용자 `me`·저장 비밀번호가 있는 서버에서 비밀번호 칸에 `pw`를 입력하고 체크했다가 다시 풀면 사용자 이름 칸이 `me`, 비밀번호 칸이 `pw`, 저장 비밀번호 표시(자리표시 "저장된 비밀번호")가 되돌아오고, 사용자 이름 칸에 포커스가 있다(AN4).
- **Test-1312** 새 서버 폼(체크됨)에서 체크를 풀면 사용자 이름 칸이 빈 채 켜지고 포커스를 받는다(AN4).
- **Test-1313** 새 서버 폼(체크됨)의 호스트 칸에 `bob@nas.local:2121`을 붙여넣으면 체크가 풀리고 사용자 이름 칸이 `bob`이다. `anonymous@nas.local:2121`을 붙여넣으면 체크된 채다(AN5).
- **Test-1314** 사용자 `me`인 저장 서버에서 체크한 뒤 관리창에서 연결하면 `ftp:connect` 인자의 사용자가 `anonymous`, 비밀번호가 `anonymous@`다(`savedPasswordOf` 없음, AN3).
- **Test-1315** 사용자 `me`·저장 비밀번호가 있는 서버에서 체크하고 저장한 뒤(저장 행의 `hasPassword`가 `false`가 됨) 체크를 풀면, 사용자 이름 칸은 `me`이고 "저장된 비밀번호 제거" 버튼이 없으며 비밀번호 칸의 자리표시가 "저장된 비밀번호"가 아니다(AN8).
- **Test-1391** 사용자 `me`·저장 비밀번호가 있는 서버에서 체크한 뒤 목록에서 같은 서버를 다시 고르면 체크가 풀리고 사용자 이름 `me`, 저장 비밀번호 자리표시가 돌아온다. 새 서버 폼에서 체크를 풀고 `bob`을 적은 뒤 "새 서버"를 다시 누르면 체크된 빈 폼이다(AN10).
- **Test-1392** 새 서버 폼(체크됨)의 호스트 칸에 `bob@nas.local`을 적고 Tab으로 떠나면 체크가 풀리고 사용자 이름이 `bob`이다. 호스트 칸에 `carol@nas.local`을 적고 곧바로 체크박스를 누르면 체크가 풀린 채이고 사용자 이름 `carol`이 남으며 사용자 이름 칸에 포커스가 있다(AN5·AN11). 체크박스에서 눌렀다가 밖에서 놓은 뒤 주소 붙여넣기로 체크가 풀리면, 누름 없는 클릭은 체크한다. pointerup 뒤 400ms 지나 호스트 칸 blur와 클릭이 와도(터치) 계정이 남고, 앞선 누름의 지우기가 새 누름의 기록을 지우지 않는다(AN11).
- **Test-1393** 새 서버 폼(체크됨)의 호스트 칸에 `bob:secret@files.example`을 적고 Enter를 치면 `ftp:connect`의 사용자·비밀번호가 `bob`·`secret`이고 체크가 풀려 사용자 이름이 `bob`이다(AN12). 체크를 풀고 사용자 이름 `me`를 적은 새 서버에서 호스트에 `bob:secret@files.example`을 적고 Enter를 치면 `bob`·`secret`으로 연결하고 툴바 주소에 `secret`이 없다. 사용자 `me`인 저장 서버의 호스트를 `bob@me.local`로 바꾸고 Enter를 치면 `ftp:saveServer`의 사용자와 연결 사용자가 `bob`이다. IME 조합을 끝내는 Enter는 호스트 칸을 나누지 않는다(AN12).
- **Test-1394** 새 서버 폼(체크됨)의 호스트 칸에 `anonymous:me@example.com@nas.local`을 붙여넣으면 체크가 풀리고 사용자 이름 `anonymous`, 비밀번호 `me@example.com`이 켜진 칸에 있다(AN13).
- **Test-1395** 사용자 이름이 비었고 저장 비밀번호가 있는 서버를 고르면 체크가 풀려 있고 비밀번호 칸이 켜져 있으며 "저장된 비밀번호" 자리표시와 "저장된 비밀번호 제거" 버튼이 있다(AN13). 사용자 이름 없이 비밀번호만 있는 초안으로 열면 체크가 풀려 있고 비밀번호 칸이 켜져 있다(AN13).

## 4. 완료 기준

1. 위 12개 케이스가 RED를 거쳐 GREEN이다. 기존 테스트는 모두 통과한다.
2. `npm run typecheck && npm run lint && npm test` 통과, 바꾼 파일은 `npx prettier --check` 통과.
3. 새 IPC 채널 없음. 새 i18n 키는 `connect.anonymous` 하나(11개 로케일).
4. Stryker: 바뀐 로직이 컴포넌트(`ServerForm`)에만 있어 `mutate`에 넣지 않는다(jsdom 렌더 테스트는 뮤턴트 점수가 단언 강도를 반영하지 못한다는 기존 방침).
5. R3(실기기): 관리창에서 익명 서버를 열면 체크됨 → 계정 서버에서 체크·저장 → 익명으로 연결됨 → 체크 해제로 입력값 복원.
