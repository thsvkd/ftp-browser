# 핸드오프: 선반 리모컨을 "알약 섬"으로 — 접힘에서 바로 보내기 · 크기 전환 · 고정 크기 필름

R1에서 인간과 합의한 내용의 고충실도 기록. R2(테스트 코드 작성)·구현의 유일한 입력이다.
이 문서에 없는 케이스는 완료 범위 밖이다. 새 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

작업 유형(R0): **디자인 교체 + 결함 수정**. RED 테스트를 먼저 세운 뒤 GREEN으로 만든다.

선행 작업: [`shelf-floating-remote.md`](./shelf-floating-remote.md)(F1~F9, v1.5.0)와 그 결함 수정
(v1.5.1, F10·F15·F20). 이 스펙은 그 위에서 **생김새·배치와 F8 하나**만 바꾼다. 담기·끌기·놓기 규칙
(F4 OS 드롭, F5 `'shelf'` 키, F6 `startDrag`, F7·F15 시작한 항목만 빼기)은 그대로다.

## 1. 문제 정의

사용자 피드백: "선반 리모컨의 디자인이 맘에 안 든다." 디자인 랩에서 4개 안(알약 섬 · 목적지 런처 ·
코너 토트 · 하단 트레이)을 같은 데이터·같은 과제로 비교했고, 인간이 **A안 "알약 섬"** 을 골랐다. 이어서
A안 미리보기에 대한 피드백 두 차례를 반영했다(아래 결정에 녹아 있다).

### 지금 상태 (v1.5.1)

- 접힌 상태는 **개수·용량 알약**뿐이다. 보내려면 펼쳐야 하고, 펼치면 320×420 카드가 화면 가운데 하단을
  덮는다. 카드 안의 부채꼴 더미(`Stack`)·세로 목록·큰 버튼이 세로로 쌓여 있다.
- 접혀 있어도 카드 본체가 `inert`·투명으로 DOM에 남아 있다(함정 D: `flyTo`가 더미를 찾는다).
- 끄는 동안 **창 전폭 56px 띠**가 뜬다. 선반에 이미 뭔가 있어도 띠와 카드가 따로 논다.
- `add()`가 담을 때마다 **카드를 펼친다**(F8) — ⇧S를 누를 때마다 카드가 탐색기를 덮는다.

## 3. 구현 함정

### 함정 A — 열린 도크를 전제한 테스트 (I8)

`add()`가 더는 열지 않으므로 **AppShell을 그리고 선반 행(`listitem`)을 찾던 테스트**는 행이 없다
(접힘엔 숨긴 본체도 없다, I1). 그 테스트들은 `setDockOpen(true)`를 **준비 단계에 명시**한다 — 단언은
바꾸지 않는다. `dockOpen`이 담기로 켜진다고 단언하던 곳(Test-874·875, Test-1245)은 §6의 개정을 따른다.

### 함정 B — jsdom에는 Web Animations·`getAnimations`·`ResizeObserver`·`matchMedia`가 없다

ShelfDock 테스트는 `HTMLElement.prototype.animate`만 흉내 낸다. 모핑·필름 훅은 **없는 API를 건너뛰어야**
한다(`typeof el.getAnimations === 'function'` 등). `reducedMotion()`은 `lib/flyTo.ts`의 것을 쓴다.

### 함정 C — 이중 놓기 대상

펼친 패널 안의 `Shelf` 본체도 `data-shelf-target`이고 섬 루트도 그렇다. 둘 다 키 `'shelf'`라 안쪽이
`stopPropagation`해도 결과는 같다. `[data-region="shelf-dock"][data-shelf-target]`(기존 테스트의 `strip()`)은
**섬 루트**를 가리켜야 하므로 루트가 둘 다 갖는다.

### 함정 D — 탐색기 전송 안내 알약과의 높이

섬은 `main` 안에 `absolute bottom-3`으로 뜬다. 알약은 탐색기 하단에서 `bottom-20`(80px)이고 섬은
12px에서 접힘 높이 54px → 위끝 66px. 접힘 상태에서는 겹치지 않는다(Test-1292 그대로). 펼친 패널은
알약을 덮는다 — 지금 카드도 그랬다(범위 밖).
