# 핸드오프: 연결된 탭의 저장 서버 목록에서 더블클릭

이 문서에 없는 케이스는 범위 밖이다. 새 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

작업 유형(R0): **버그 수정**. RED 테스트를 먼저 세워 실패를 확인한 뒤 GREEN으로 만든다.

## 1. 문제 정의

연결된 탭에서 툴바의 서버 버튼으로 저장 서버 목록을 열면, 행을 **한 번 클릭**하는 것만으로 그 서버로
전환하고 목록을 닫는다(이미 그 탭의 서버면 닫기만 한다). 연결되지 않은 탭의 같은 목록은 클릭이 고르기,
더블클릭이 연결이라 사용자는 더블클릭에 익숙하다. 더블클릭하면 첫 클릭이 목록을 닫으므로 두 번째 누름이
목록 아래에 있던 것(대개 탐색기)에 닿는다.

- 포커스가 툴바 밖으로 나가 입력 모드가 끝난다(v1.5.1 F18). 비밀번호를 받아야 하는 서버면 방금 나타나
  포커스를 받은 비밀번호 칸이 사라진다.
- 탐색기 항목을 고르거나, 더블클릭으로 그 폴더·파일을 연다.

CI 플레이크 조사에서 드러났다: Test-1277·1306이 느린 러너에서 두 번째 누름이 비밀번호 칸의 포커스를
빼앗아 실패했다.

## 2. 결정

| ID  | 결정                                                                                                                                                                                                                                | 이유                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| C1  | 연결된 탭의 목록에서 클릭으로 목록을 닫으면(다른 서버로 전환, 지금 서버를 다시 고름), 같은 더블클릭의 나머지(두 번째 누름의 pointerdown·mousedown·mouseup·click·dblclick)를 창의 capture 단계에서 삼킨다(기본 동작과 전파를 막는다) | 두 번째 누름이 포커스를 옮기거나 아래 항목을 고르거나 열지 않는다                                     |
| C2  | "같은 더블클릭"은 마우스 이벤트는 클릭 횟수(`detail` ≥ 2), 횟수가 없는 pointerdown은 첫 클릭 자리에서 8px 안인지로 가린다. `detail` 1인 새 클릭, dblclick, 또는 600ms가 지나면 그만둔다                                             | 이어지는 새 클릭과 다른 자리의 누름은 그대로 둔다. 600ms는 Windows 기본 더블클릭 시간(500ms)을 덮는다 |

### 기각한 대안

- **연결된 탭에서도 클릭은 고르기, 더블클릭은 전환**: 한 번 클릭으로 바꾸는 동작은 서버 버튼 목록의 정해진 동작이다(server-connect-activation). 바꾸지 않는다.
- **목록을 바로 닫지 않고 더블클릭 시간만큼 남겨 두기**: 전환이 늦어 보이고, 남은 목록이 두 번째 클릭을 받아 다시 고르게 된다.

## 4. 완료 기준

- Test-1396·1397이 수정 전 실패(1397은 새 모듈), 수정 후 통과. `npm run typecheck && npm run lint && npm test`.
- R3: 실제 앱에서 연결된 탭의 서버 목록 행을 더블클릭하면 서버가 바뀌고(비밀번호가 필요하면 비밀번호 칸이 포커스를 가진 채 남고) 목록 아래 탐색기 항목은 열리지 않는다.
