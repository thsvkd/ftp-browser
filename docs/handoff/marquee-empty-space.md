# 핸드오프: 항목 아래 빈 곳에서 시작한 마퀴(드래그 선택)

이 문서에 없는 케이스는 범위 밖이다. 새 케이스를 추가하거나 기존 케이스를 재해석하지 말 것.

작업 유형(R0): **버그 수정**. RED 테스트를 먼저 세워 실패를 확인한 뒤 GREEN으로 만든다.

---

## 1. 문제 정의

사용자 피드백: _"서버로 연결되어 보여지는 파일뷰에서는 드래그로 여러 파일을 선택하는 기능이 안먹히네."_
R1에서 증상은 "빈 곳에서 끌어도 선택 사각형이 전혀 나타나지 않는다"로 확인했다.

### 원인

마퀴 `onMouseDown`은 `FileGrid`·`FileList`의 루트 div에 달려 있고, 그 div는
`style={{ height: <가상 목록 전체 높이>, minHeight: '100%' }}`로 스크롤 영역을 채우려 한다. 그런데
`Explorer.tsx`가 그 사이에 흐림·대기 표시용 래퍼(`transition-opacity`)를 두면서 래퍼 높이가
`auto`가 되었다. 높이가 정해지지 않은 부모에 대한 퍼센트 `min-height`는 무시되므로, 루트 div는 항목
높이만큼만 차지한다.

항목이 화면을 다 채우지 못하는 폴더에서는 마지막 항목 아래 빈 곳이 루트 div 밖(스크롤 영역 자신)이
되어 mousedown이 마퀴에 닿지 않는다. 로컬 홈처럼 항목이 많은 폴더는 화면을 다 채워 드러나지 않고,
항목이 적은 원격 폴더에서 먼저 드러났다. 실제 앱(R3, pyftpdlib)에서 파일 두 개인 원격 폴더의 그리드
루트 높이는 249px, 스크롤 영역은 583px였고 그 아래에서 끈 드래그는 아무것도 고르지 않았다.

기존 마퀴 테스트(Test-858 등)는 루트 div에 직접 mousedown을 보내고 jsdom은 레이아웃을 계산하지
않아 이 결함을 잡지 못했다.

## 2. 결정

| ID  | 결정                                                                                                     | 이유                                                                                                 |
| --- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| M1  | 목록 래퍼에 `h-full`을 준다. 래퍼가 스크롤 영역 높이를 갖게 되어 루트 div의 `minHeight: '100%'`가 풀린다 | 래퍼는 항목이 있을 때만 그려지므로(`showList`) 빈 폴더·오류 패널의 `min-h-full` 배치와 겹치지 않는다 |
| M2  | 항목이 화면보다 많으면 루트 div가 래퍼 밖으로 넘친다(`overflow: visible`). 스크롤 높이는 그대로 유지된다 | 래퍼의 흐림(`opacity`)·대기(`pointer-events-none`)는 자손에 그대로 적용된다                          |

### 기각한 대안

- **마퀴 핸들러를 스크롤 영역으로 옮기기**: 같은 효과지만 마퀴 훅·오버레이를 `Explorer`로 끌어올려야 하고
  빈 폴더·오류 패널을 다시 걸러야 한다. 원인은 높이 한 줄이다.
- **래퍼에 `min-h-full`**: 래퍼 높이가 여전히 정해지지 않아 안쪽 퍼센트 `min-height`가 풀리지 않는다.

## 4. 완료 기준

- Test-1329가 수정 전 실패, 수정 후 통과.
- R3: 실제 앱에서 항목이 적은 원격 폴더의 그리드·리스트 모두, 마지막 항목 아래 빈 곳에서 시작한 드래그가
  사각형을 그리고 항목을 고른다. 항목이 많은 폴더의 스크롤과 마퀴, 빈 폴더 안내의 가운데 정렬은 그대로다.
